# 오픈스카이 도티 안내 사이트 설계

오픈스카이의 앱을 소개하고 Google AdMob이 앱 소유권을 확인할 수 있도록 GitHub Pages 사이트를 운영한다. 첫 공개 대상은 도티두잇이며, 이후 다른 앱의 안내 페이지를 같은 사이트에 추가할 수 있게 한다.

## 범위와 보호 대상

- 저장소: `git@github.com:opensky-doti/opensky-doti.github.io.git`
- 공개 호스트: `https://opensky-doti.github.io`
- 로컬 작업 경로: `/Users/opensky/doti/opensky-doti.github.io`
- 기존 도티두잇·도티모티·공유 모듈·백엔드·법적 고지 저장소는 수정하지 않는다.
- 기존 APK, AAB, 서명키, 앱의 광고 모드와 광고 ID를 변경하지 않는다.
- 새 사이트에서 광고를 송출하거나 결제·로그인·회원가입을 제공하지 않는다.
- 도티모티는 출시·공개 범위가 확정되기 전까지 다운로드나 연동 기능을 홍보하지 않는다.

## 페이지와 공개 정보

| 경로 | 내용 |
| --- | --- |
| `/` | 오픈스카이 도티 앱 안내, 도티두잇 소개 페이지로 연결, 문의 |
| `/dotidoit/` | 미션·수행툴·수행 기록에 대한 간단한 소개, Play 다운로드, 개인정보처리방침과 문의 링크 |
| `/app-ads.txt` | 회사 AdMob 게시자 코드가 담긴 일반 텍스트 |
| `/404.html` | 잘못된 주소 안내와 홈으로 돌아가는 링크 |

도티두잇 Play 링크는 `https://play.google.com/store/apps/details?id=com.doti.doit`를 사용한다. 문의 이메일은 사용자가 지정한 `eonseok.yoon@opensky.co.kr`이다. 회사 표기는 사용자가 확인한 `오픈스카이`로 한다. 확인하지 않은 법인 접두사·주소·사업자등록번호는 추가하지 않는다.

개인정보처리방침은 기존 주소 `https://kizwond.github.io/dotimoti-legal/dotidoit/privacy/`에 연결한다. 이번 작업에서는 본문을 복제하거나 개정하지 않는다. 실광고 출시 전 공개 방침의 광고 관련 내용 검토는 별도 작업이다.

기능 소개는 현재 독립 앱의 미션, 수행툴, 수행 기록을 중심으로 작성한다. 제거한 장소 도착 알림, 앱 간 연동, 검증하지 않은 효능이나 광고 수익·심사 통과를 보장하는 문구를 넣지 않는다.

## 광고 인증 파일

사이트 최상위 파일의 내용은 사용자가 AdMob에서 제공한 다음 한 줄과 마지막 줄바꿈이다.

```text
google.com, pub-3081928577042149, DIRECT, f08c47fec0942fa0
```

이 공개 게시자 코드는 비밀키가 아니다. 파일은 HTML 페이지로 바뀌거나 인증 화면으로 이동하지 않고, `/app-ads.txt`에서 직접 읽혀야 한다. 일반 하위 폴더에만 게시하지 않는다.

같은 회사 AdMob 계정의 다른 앱이 같은 호스트를 개발자 웹사이트로 사용하면 이 파일을 함께 이용할 수 있다. 새 앱의 AdMob 등록·광고 단위 생성·심사는 별도로 필요하다. 다른 광고 계정이나 네트워크를 추가할 때는 승인된 판매자 정보를 검토하며 기존 줄을 무조건 덮어쓰지 않는다.

## 화면과 기술 구성

빌드 프레임워크와 런타임 서버 없이 HTML과 CSS로 만든다. 사이트 코드는 `site/`에 두고 문서·테스트·배포 설정과 분리한다. 공통 스타일은 `site/assets/styles.css`, 각 페이지는 해당 경로의 `index.html`로 구성한다.

흰색 중심의 배경과 파란색 강조색을 사용하고, 넓은 화면은 읽기 좋은 최대 너비를 둔다. 좁은 휴대폰 화면에서는 한 열로 배치한다. 시스템 글꼴을 사용하며 외부 폰트·추적 스크립트·분석 SDK를 추가하지 않는다. 기존 확정 아이콘을 사용한다면 원본을 확인한 뒤 복사하며 원본 파일은 변경하지 않는다.

문서 언어, 페이지 제목, 설명, 논리적인 제목 단계, 키보드 초점, 읽기 쉬운 대비와 링크 이름을 제공한다. 320px 너비 및 글자 확대에서도 내용과 버튼이 잘리거나 가로 스크롤이 생기지 않게 검증한다.

사이트 자체에는 데이터 입력 폼·쿠키·로컬 저장 기능을 넣지 않는다. GitHub 호스팅의 접근 로그까지 수집하지 않는다고 주장하지 않는다.

## 배포와 운영

GitHub Actions에서 정적 파일과 링크 구조를 검증한 뒤 `site/`만 Pages 산출물로 배포한다. 공개 배포는 `main` 기준으로 하며 PR 검증은 배포하지 않는다. 워크플로 권한은 작업별 필요한 범위로 한정한다. 문서와 테스트 파일은 공개 사이트 산출물에 포함하지 않는다.

저장소 Pages 설정은 GitHub Actions를 배포 소스로 지정해야 한다. 기존 SSH 연결만으로 GitHub 웹 설정 권한을 확보했다고 간주하지 않는다. 인증된 관리 수단을 사용할 수 없으면 사용자에게 필요한 설정 한 단계만 안내하고, 실제 배포 성공 여부를 별도로 확인한다. 비밀번호·토큰을 대화에 요청하지 않는다.

README에는 로컬 확인, 파일 수정, 배포, 공개 URL 점검, 이전 정상 커밋으로 되돌리는 절차와 후속 앱 추가 방법을 남긴다. 반영 취소는 원격 기록을 강제로 덮어쓰지 않고 revert 커밋과 재배포를 기본으로 한다.

## 검증과 완료 기준

- 인증 파일의 정확한 게시자 코드, 줄바꿈과 위치를 자동 검사한다.
- 두 안내 페이지의 필수 링크와 로컬 파일 경로를 자동 검사한다.
- 잘못된 링크나 광고 인증 값이 검증에서 실패하는지도 확인한다.
- 브라우저에서 휴대폰·데스크톱 화면, 키보드 이동, 확대 상태를 확인한다.
- 배포 후 HTTPS의 `/`, `/dotidoit/`, `/app-ads.txt` 응답을 직접 확인한다. 인증 파일은 HTTP 200과 올바른 일반 텍스트 내용이어야 한다.
- 존재하지 않는 URL에서 오류 안내와 홈 링크를 확인한다.
- 소스·운영 문서가 원격에 반영됐는지와 실제 Pages 배포 결과를 구분해 보고한다.

사이트가 정상 공개된 후 사용자가 Play Console 웹사이트에 `https://opensky-doti.github.io/dotidoit/`를 입력하고 공개 반영한다. 이후 AdMob에서 업데이트 확인을 요청한다. 파일 공개와 AdMob 인증 완료는 다르므로 콘솔 결과를 확인하기 전에는 인증 완료라고 보고하지 않는다. Google의 반영 대기 시간이 발생할 수 있다.
